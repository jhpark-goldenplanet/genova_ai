# Local Demo Build Plan

## 목적

- 내일 오전 시연용 로컬 실행본에서 실제 업로드와 실제 분석 결과 확인이 가능하도록 최소 구현 범위를 고정한다.
- 개발서버의 mock 기반 흐름은 유지하고, 로컬 실행본만 실제 기능 연결 대상으로 본다.

## 시연 환경 분리

### 로컬 실행본

- 목적: 실제 동작 검증
- 기준 흐름: `새 프로젝트 -> 영상 업로드 -> 분석 프리셋 설정 -> 분석 시작 -> 결과 확인 -> 분할 다운로드`
- 실제 동작 범위
- 영상 업로드
- 기존 백엔드 분석 파이프라인 실행
- 단일 분석 결과 표시
- 요약 탭 표시
- 분할 탭 표시
- 분할 다운로드

- 시연용 임시 허용 범위
- 프리셋 선택과 저장 UI
- 재분석 UI
- 다중 분석 버전 관련 흔적 중 일부 로컬 상태 유지

### 개발서버

- 목적: 새 UX 흐름 설명
- 기준: 현재 로컬스토리지 기반 mock 흐름 유지
- 실제 분석 연동은 이번 작업 범위에서 제외

## 이번 작업의 제품 판단

- 실제 분석 결과는 원본 영상당 단일 결과 기준으로 시연한다.
- 다중 분석 버전 비교는 이번 로컬 시연 목표에서 제외한다.
- 현재 UI 구조는 유지하되, 실제 기능 연결은 단일 결과 흐름으로 단순화한다.
- 프리셋 설정과 재분석은 시연 중 설명 가능한 수준으로만 남기고 실제 분석 반영까지 요구하지 않는다.

## 시연 핵심 화면

### 1. 워크스페이스 목록

- 핵심 액션: `새 프로젝트` 진입
- 시연 포인트: 새 구조의 시작 화면과 프로젝트 진입 방식 설명

### 2. 새 프로젝트 / 업로드 화면

- 핵심 액션: 실제 영상 업로드 후 분석 시작
- 시연 포인트: 프리셋 설정 UI를 거쳐 실제 분석이 시작되는 흐름

### 3. 결과 상세 - 요약

- 핵심 액션: 분석 완료 후 요약 결과 확인
- 시연 포인트: 기존 분석 기능이 새 UI 안에서 이어지는 모습

### 4. 결과 상세 - 분할

- 핵심 액션: 분할 결과 확인 및 다운로드
- 시연 포인트: 실제 활용 가능한 결과 산출물 제시

## 역할 분리

### 역할 기능개발

- 실제 업로드 API와 분석 파이프라인을 현재 새 프로젝트 흐름에 연결
- 단일 분석 결과 기준으로 결과 페이지 데이터 연결
- 분할 다운로드 동작 점검
- 로컬 실행 환경에서 성공 경로를 우선 보장

### 역할 화면개발

- 시연 흐름 기준으로 문구, 버튼, 상태 화면 정리
- 단일 결과 기준으로 버전 관련 UI 노이즈 축소
- 요약/분할/설정 화면의 연결감을 높이도록 시각 정리
- 개발서버 mock 흐름은 유지하되 시연에 불필요한 혼란 요소 제거

## 제외 범위

- 작업/분석 버전의 백엔드 정보구조 신설
- 프리셋 영속 저장
- 재분석의 실제 서버 반영
- 기관 구독/토큰 풀 실데이터 연동
- 개발서버를 실제 분석 구조로 전환하는 작업

## 완료 기준

- 로컬에서 새 프로젝트 생성 후 실제 영상 업로드 가능
- 업로드 후 실제 분석 완료까지 도달 가능
- 결과 상세에서 요약과 분할 결과 확인 가능
- 분할 다운로드 성공
- 시연 경로에서 다중 버전 개념이 혼란을 주지 않음

## 우선순위

- P0: 로컬 업로드/분석/결과/다운로드 성공 경로 확보
- P0: 시연 중 노출되는 UI 혼란 요소 제거
- P1: 프리셋/재분석 시연용 문구 정리
- P1: 개발서버 mock 흐름의 일관성 보완
