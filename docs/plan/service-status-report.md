# Service Status Report

## 목적

- 현재 Genova AI 프로젝트에서 구현 완료된 기능을 서비스 관점으로 요약한다.
- 실제 서비스 전환 시 반드시 추가 개발이 필요한 항목을 정리한다.
- 이후 제품 경쟁력을 높이기 위한 고도화 제안 항목을 분리해 정리한다.

## 1. 현재 구현 완료된 기능

### 1-1. 영상 업로드와 처리 파이프라인

- 대용량 영상 업로드를 위한 GCS Signed URL 기반 업로드 흐름 구현
- 업로드 확인 후 백엔드 비동기 처리 파이프라인 시작
- URL 기반 영상 업로드 지원
- 처리 상태 조회 API와 진행률 단계별 조회 지원

정리
- 사용자는 영상을 업로드하고 처리 진행 상황을 확인할 수 있다.
- 시스템은 업로드 이후 백그라운드에서 분석 파이프라인을 수행한다.

### 1-2. AI 기반 분석 결과 생성

- Gemini 기반 영상 분석 실행
- 영상 전체 요약 생성
- 키워드 추출
- 구간별 제목, 요약, 스크립트, 키워드 생성
- 분석 결과 조회 API 제공

정리
- 영상 1건에 대해 실제 분석 결과를 생성하고 조회할 수 있다.

### 1-3. 자막과 구간 정보 제공

- 구간별 스크립트 저장 구조 보유
- 구간 시작/종료 시간, 제목, 요약, 분류 정보 저장
- 결과 화면에서 요약, 스크립트, 분할 탭 구조 구현

정리
- 분석 완료 후 사용자는 구간별 텍스트와 분할 결과를 확인할 수 있다.

### 1-4. 영상 분할 다운로드

- 영상 구간별 다운로드 URL 생성 API 구현
- 선택 구간 개별 다운로드 지원
- 선택 구간 일괄 다운로드 지원
- 썸네일 이미지 포함 다운로드 옵션 지원

정리
- 현재 기준으로 “분석 후 결과 활용”까지 이어지는 핵심 기능이 이미 구현되어 있다.

### 1-5. 다국어 번역 기반 결과 조회

- 영상 전체 결과 번역 구조 보유
- 구간별 번역 구조 보유
- 요청 언어 기준 on-demand 번역 생성 및 재사용 구조 보유

정리
- 다국어 확장 가능성이 이미 백엔드 구조에 반영되어 있다.

### 1-6. 운영/모니터링 기반

- Health Check API
- Monitoring API
- 처리 상태 추적
- Redis 기반 진행 상태 관리
- GCP 기반 스토리지 및 배포 구조 보유

정리
- 개발/운영 관점의 최소 모니터링 기반은 이미 갖춰져 있다.

### 1-7. 프론트엔드 화면 기반

- 워크스페이스 진입 구조
- 새 프로젝트 / 새 작업 UI
- 결과 상세 화면
- 관리 페이지
- 설정 화면

주의
- 워크스페이스, 분석 버전, 프리셋, 재분석 관련 일부 화면은 실제 서비스 데이터가 아니라 localStorage 기반 mock 흐름이 포함되어 있다.
- 따라서 화면은 선구축되어 있으나, 일부는 실제 서비스 기능으로 아직 완결되지 않았다.

## 2. 실제 서비스 전환 시 반드시 개발해야 할 기능

### 2-1. 작업/프로젝트 정보구조 실구현

- 현재 분석 결과는 사실상 `영상 1건` 중심 구조다.
- 실제 서비스에서는 `사용자 -> 워크스페이스/프로젝트 -> 영상 -> 분석결과` 구조가 필요하다.
- 작업 목록, 재방문, 검색, 정렬, 상태 관리가 가능하도록 DB 모델과 API를 확장해야 한다.

### 2-2. 인증/권한/기관 단위 운영 구조

- 현재는 개발 편의 중심 인증 구조가 포함되어 있다.
- 실제 서비스에서는 기관/사용자/권한 레벨 관리가 필요하다.
- 멤버 관리, 기관 관리자 권한, 접근 제어, 감사 로그가 필요하다.

### 2-3. 프론트 mock 기능의 실제 백엔드 연동

- 워크스페이스 목록
- 새 프로젝트 생성
- 프로젝트 상세
- 프리셋 저장/조회
- 재분석 요청
- 분석 버전 관리

정리
- 현재 UI에 있는 핵심 플로우를 실제 데이터 기반으로 전환해야 한다.

### 2-4. 프리셋과 프롬프트 적용 기능

- 현재 프리셋 UI는 존재하지만 실제 Gemini 호출에 반영되지 않는다.
- 프리셋 저장, 선택, 적용, 이력 관리가 필요하다.
- 어떤 프롬프트로 생성된 결과인지 추적 가능해야 한다.

### 2-5. 재분석과 분석 버전 관리

- 같은 원본 영상에 대해 다른 설정으로 재분석하는 요구가 이미 존재한다.
- 실제 서비스에서는 분석 결과 버전 관리, 기본 버전 지정, 버전 비교, 재생성 이력이 필요하다.

### 2-6. 결과 편집 및 저장 기능

- 실제 서비스에서는 생성된 요약/스크립트/분할 결과를 사용자가 수정하고 저장할 수 있어야 한다.
- 수정 이력, 승인 상태, 최종본 개념이 필요할 수 있다.

### 2-7. 운영 안정성 강화

- 실패 시 재시도 정책
- 장시간 작업 모니터링
- 작업 취소 이후 정리
- 대용량/동시 처리 시 큐 관리
- 에러 알림과 운영 대시보드

정리
- 개발환경 수준의 파이프라인에서 서비스 운영 수준의 안정성으로 끌어올리는 작업이 필요하다.

### 2-8. 결제/구독/토큰 관리

- 현재 관리 화면은 초안 수준이다.
- 실제 서비스에서는 기관 단위 플랜, 토큰 사용량, 소진 내역, 갱신 정책, 운영자 조정 기능이 필요하다.

### 2-9. 데이터 보관 정책과 보안

- 업로드 원본 보관 기간
- 결과물 보관 정책
- 다운로드 URL 만료 정책
- 개인정보/민감정보 대응
- 삭제 요청 처리

## 3. 고도화 제안 항목

### 3-1. 분석 품질 고도화

- 프롬프트 프리셋 체계화
- 도메인별 분석 템플릿 제공
- 결과 품질 평가 지표 도입
- 분석 실패/품질저하 케이스 재학습용 수집 체계

### 3-2. 협업 기능

- 프로젝트 단위 공유
- 멤버별 코멘트
- 결과 승인 플로우
- 편집 이력 비교

### 3-3. 검색과 재사용성 강화

- 과거 분석 검색
- 키워드/주제 기반 필터
- 프리셋 재사용
- 결과 복제 후 재분석

### 3-4. 결과 활용 기능 확장

- 요약/스크립트/분할 결과의 다양한 포맷 export
- 교육자료 형태의 자동 재구성
- 구간별 클립 재조합
- 썸네일/타이틀 추천

### 3-5. 운영 관리자 기능 강화

- 기관별 사용 현황 대시보드
- 실패 작업 모니터링
- 처리시간/비용 통계
- 모델별 성능 비교

### 3-6. AI 기능 확장

- 사용자 프롬프트 실제 반영
- 멀티모달 분석 옵션 세분화
- 요약 톤/길이/목적별 생성
- 질의응답형 후속 분석

## 4. 경영진 공유용 요약

### 현재 수준

- 업로드, 실제 AI 분석, 요약/스크립트/구간 생성, 분할 다운로드까지 이어지는 핵심 기능은 이미 구현되어 있다.
- 즉, 단순 PoC를 넘어서 핵심 분석 파이프라인은 작동 가능한 수준이다.

### 서비스 전환 시 핵심 과제

- 현재 부족한 부분은 AI 분석 자체보다 서비스 운영 구조다.
- 특히 프로젝트 구조, 사용자/권한, 프리셋 적용, 재분석 버전 관리, 운영 안정성, 과금/토큰 관리가 주요 과제다.

### 투자 우선순위 제안

- 1단계: 현재 실제 분석 기능을 새 UI에 안정적으로 이관
- 2단계: 프로젝트/워크스페이스/프리셋/재분석의 실데이터 구조 구현
- 3단계: 운영/과금/권한 관리 체계 고도화
- 4단계: 협업, 검색, 품질평가, 고급 AI 기능으로 확장
