# Multi Terminal Workflow

여러 Claude Code 터미널을 병렬로 사용할 때의 기본 운영 방식이다.

## 목적

- 세션별 역할을 분리해 컨텍스트 오염을 줄인다.
- 동시에 여러 작업을 진행해도 충돌을 줄인다.
- 완료 후 다음 계획 갱신이 자연스럽게 이어지게 한다.

## 기본 구조

- `docs/plan/`: 큰 방향과 우선순위
- `docs/progress/`: 현재 진행 중인 작업
- `docs/done/`: 완료된 작업
- `docs/agent/roles/`: 터미널 역할 정의

## 문서 역할 구분

- `docs/plan/`은 프로젝트의 큰 방향, 우선순위, 로드맵 상태를 관리한다.
- `docs/progress/`는 현재 진행 중인 작업의 담당자, 범위, 최근 업데이트를 관리한다.
- `docs/done/`은 완료된 작업의 결과와 후속 과제를 기록한다.

### `docs/plan/`에 적는 것

- 기능, 화면, 리팩터링 단위의 우선순위
- 항목별 상태: `예정`, `진행중`, `완료`
- 다음 단계에서 이어질 큰 과제

### `docs/plan/`에 적지 않는 것

- 세션 단위 작업 로그
- 담당 터미널, 점유 경로
- 디버깅 과정, 시행착오
- 완료 결과의 상세 설명

### `docs/progress/`에 적는 것

- 담당 역할
- 담당 터미널
- 대상 경로
- 작업 범위
- 제외 범위
- 최근 업데이트
- 다음 액션

### `docs/done/`에 적는 것

- 무엇을 완료했는지
- 어디를 변경했는지
- 왜 그렇게 변경했는지
- 남은 후속 작업

## 기능 단위 문서 원칙

- 문서는 계속 기능 단위로 관리한다.
- 같은 기능이라도 문서 목적에 따라 `docs/plan/`, `docs/progress/`, `docs/done/`에 나눠 기록한다.
- 폴더는 기능 분류가 아니라 문서 역할 분류다.
- 예시: `workspace` 기능은 `docs/plan/workspace-roadmap.md`, `docs/progress/workspace-ui.md`, `docs/done/workspace-ui-phase1.md`처럼 분리할 수 있다.

## 기본 흐름

1. 작업 시작 전에 `docs/plan/INDEX.md`를 보고 현재 우선순위를 확인한다.
2. 사용자가 역할 호출을 말하면 해당 역할 문서를 자동으로 확인한다.
3. 작업을 시작하면 `docs/progress/`에 작업 문서를 만든다.
4. 진행 중 변경사항은 `최근 업데이트`에 짧게 누적한다.
5. 완료되면 `docs/done/`으로 옮기고 결과와 후속 작업을 남긴다.
6. 큰 방향이 바뀌면 `docs/plan/INDEX.md`를 갱신한다.

## 운영 원칙

- `plan`은 기준 문서다. 실시간 작업 로그를 과도하게 넣지 않는다.
- `progress`는 현재 상태 문서다. 누가 무엇을 잡고 있는지 명확해야 한다.
- `done`은 결과 문서다. 무엇이 끝났고 무엇이 남았는지 요약한다.
- `plan`의 `진행중`은 로드맵 상태를 뜻한다. 세션 로그는 `progress`에 남긴다.
- `plan`의 `완료`는 상태 표시만 남긴다. 완료 상세는 `done`에 남긴다.
- 한 세션은 가능하면 한 역할과 한 작업 문서에 집중한다.
- 한 터미널이 다른 기능이나 다른 화면 작업까지 동시에 끌고 가지 않는다.
- 새 기능이나 새 화면 작업은 가능하면 새 터미널과 새 `docs/progress/*.md` 문서로 분리한다.
