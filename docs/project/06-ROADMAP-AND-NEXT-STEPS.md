# Genova AI - 로드맵 및 향후 계획

## 현재 단계 정의

현재는 **MVP 검증 단계**이다. 핵심 AI 분석 파이프라인은 동작하며, UI가 선행 구축되어 시연/피드백 수집이 가능한 상태이다. 다음 단계는 mock으로 동작하는 프론트엔드 기능을 실제 백엔드와 연동하여 서비스 가능한 수준으로 끌어올리는 것이다.

---

## 투자 우선순위 (4단계)

### 1단계: 현재 분석 기능을 새 UI에 안정적으로 이관
- 기존 분석 파이프라인과 새 워크스페이스 UI 연결
- 단일 영상 → 단일 분석 결과 기준으로 E2E 동작 보장

### 2단계: 프로젝트/워크스페이스/프리셋/재분석 실데이터 구현
- 사용자 → 프로젝트 → 영상 → 분석결과 DB 모델 확장
- 프리셋 저장/적용/이력 관리
- 분석 버전 관리 및 재분석

### 3단계: 운영/과금/권한 관리 체계 고도화
- 기관/사용자/관리자 역할 체계
- 토큰 사용량 추적, 구독 플랜 관리
- 운영 대시보드, 에러 알림

### 4단계: 협업, 검색, 품질평가, 고급 AI 기능 확장
- 프로젝트 공유, 코멘트, 승인 플로우
- 과거 분석 검색, 키워드 필터
- 분석 품질 평가 지표, 도메인별 분석 템플릿

## P1 로드맵 상세

### P1-1. 워크스페이스 기반 분석 흐름

**목표**: 업로드 결과가 휘발되지 않고, 작업 단위로 재방문 가능한 구조

| 항목 | 상태 | 설명 |
|------|------|------|
| 새 작업 진입점 | 완료 | UI 구현 완료 |
| 작업 목록 (리스트/카드) | 완료 (mock) | localStorage 기반 |
| 작업 상세 (요약/스크립트/분할 탭) | 완료 | 탭 구조 구현 |
| 작업당 원본영상 1개 구조 | 부분 구현 | 프론트 목업 기준 |
| 분석 버전(A/B) 생성 흐름 | 부분 구현 | 프론트 임시 저장 기준 |
| 프롬프트 프리셋 저장/재사용 | 부분 구현 | 프론트 임시 저장 기준 |
| **분석 버전 비교** | **미구현** | 백엔드 모델/API 필요 |
| **버전별 설정/프롬프트 이력 서버 저장** | **미구현** | 백엔드 모델/API 필요 |
| **작업/분석 정보 백엔드 연동** | **미구현** | DB 모델 확장 필요 |

### P1-2. 분석 시작 흐름 재정의

**목표**: 업로드 즉시 분석이 아닌, 설정 기반 분석 시작 흐름

| 항목 | 상태 | 설명 |
|------|------|------|
| 영상 업로드 → 분석 설정 → 분석 시작 | 완료 | 화면 흐름 반영 |
| AI 자동 분석 (기본 모드) | 완료 | 기본값으로 설정 |
| 커스텀 분석 모드 UI | 완료 | 사용자 프롬프트 입력 |
| **분석 설정값 백엔드 저장** | **미구현** | 파이프라인 연동 필요 |
| **업로드 후 서버 기준 상태 관리** | **미구현** | |

### P1-3. 관리 정보구조 개편

**목표**: 회원 관리와 구독 정보를 관리 영역으로 통합

| 항목 | 상태 | 설명 |
|------|------|------|
| 사이드 메뉴 관리 진입 | 완료 | |
| 회원 관리 + 구독 정보 화면 분리 | 완료 | |
| 구독 정보 표시 UI | 완료 | |
| 기관 공용 토큰 풀 (문구/목업) | 부분 구현 | |
| **토큰 풀 실제 데이터 구조** | **미구현** | |
| **플랜 변경 → 운영자 반영 프로세스** | **미구현** | |
| **회원/구독 실데이터 연동** | **미구현** | |

## 백엔드 개발자 합류 후 우선 착수 영역

### 즉시 착수 가능 (기존 백엔드 코드 이해 후)

1. **프로젝트/워크스페이스 DB 모델 설계**
   - `users` → `workspaces/projects` → `videos` → `analyses` 관계 구조
   - 현재 `videos` 테이블 중심 구조를 확장

2. **분석 설정/프리셋 API**
   - 프리셋 CRUD API
   - 분석 요청 시 프리셋/커스텀 프롬프트를 Gemini 호출에 실제 반영

3. **워크스페이스 API**
   - 프로젝트 CRUD
   - 프로젝트별 영상 목록
   - 영상별 분석 결과 목록 (버전 관리)

### 중기 과제

4. **인증/권한 체계**
   - Firebase Auth → 백엔드 사용자 모델 연동
   - 기관/관리자/일반 사용자 역할 분리

5. **결과 편집 API**
   - 요약/스크립트/분할 결과 사용자 수정 및 저장

6. **운영 안정성**
   - 작업 큐 도입 (대용량 동시 처리)
   - 실패 재시도 정책 고도화
   - 운영 알림 시스템

## 결정 사항 요약 (2026-03-11 합의)

- UI 선행 개발 후 백엔드 병행
- 업로드 즉시 분석이 아닌 **업로드 → 분석 설정 → 사용자 시작** 구조
- 분석 기본 모드는 **AI 자동 분석**, 옵션으로 **커스텀 분석**
- 원본 1개에 대해 **분석 버전(A/B) 비교** 가능 구조
- 토큰 정책은 사용자별이 아닌 **기관 공용 토큰 풀**
- 구독 플랜: **Basic / Plus / Pro** (3단계, 결제는 수동 반영)
- 메뉴 구조: **워크스페이스 / 관리 / 공지사항** + 하단 **내 정보 / 설정**
